# Changelog

## 0.2.0 - 2026-10-12
- Added versioned loader/kernel BootInfo ABI and memory-map records.
- Added bounded physical frame allocator with overflow checks.
- Added dependency-free spin lock.
- Added x86-64 MSR read/write primitives and syscall MSR constants.
- Replaced direct syscall pointer dereferences with chunked usercopy boundaries.
- Added early security invariants and milestone 2A roadmap entry.

## 0.3.0 - 2026-10-12
- Centralized Linux x86-64 syscall numbers and UAPI structure layouts.
- Added identity, PID/TID, close, fstat, brk, arch_prctl, set_tid_address, robust-list and prlimit bootstrap behavior.
- Added FS-base process state needed by libc thread-local storage setup.
- Added System V AMD64 auxiliary-vector builder for future ELF exec.
- Kept unsupported memory, signal, futex, filesystem and clock calls explicit as ENOSYS rather than faking success.

## 0.4.0 - 2026-10-12
- Replaced alignment-sensitive ELF casting with a bounds-checked byte parser.
- Added strict ELF64 PT_LOAD planning, overflow checks, interpreter detection and entry validation.
- Added a fixed-capacity userspace VMA ledger with placement, overlap checks, protection and removal.
- Added anonymous mmap, mprotect and munmap ABI paths without pretending hardware PTEs already exist.
- Added ENODEV and EEXIST errno values.

## 0.5.0 - 2026-10-12
- Added a complete allocation-free AMD64/Linux initial stack builder for argc, argv, envp and auxv.
- Added AT_RANDOM, AT_EXECFN and ELF metadata placement with bounds and NUL checks.
- Added a transaction-friendly ELF execution planner with page-aligned PT_LOAD mappings and a guarded user stack reservation.
- Added E2BIG and explicit limits for bootstrap argument and environment vectors.

## 0.6.0 - 2026-10-12
- Added a freestanding C/assembly UEFI application entry and BOOTX64.EFI build path.
- Added UEFI GetMemoryMap allocation, descriptor translation and bounded ExitBootServices retry loop.
- Connected validated BootInfo to the physical allocator and CPU descriptor initialization path.
- Added x86-64 four-level page-table map, unmap, protect, CR3 activation and INVLPG primitives.
- Added GDT, long-mode TSS, ring-0 stack, IST stack and IDT construction.
- Added fatal default, double-fault and page-fault assembly entry paths with CR2 diagnostics.

## 0.7.0 - 2026-10-12
- Added IA32_EFER/STAR/LSTAR/FMASK programming for 64-bit SYSCALL.
- Added assembly syscall entry, user-RSP capture, kernel-stack switch, register preservation and Rust dispatch.
- Added lower-canonical SYSRET RIP/RSP validation and fatal fallback.
- Added an iretq ring-3 entry trampoline with user selector and context validation.
- Added a no-libc static Linux acceptance ELF using only write and exit_group.

## 0.8.0 - 2026-10-12
- Added a COFF Rust-kernel build path and single-image BOOTX64.EFI link pipeline.
- Embedded the static Linux acceptance ELF into the UEFI image and exported it through BootInfo initrd fields.
- Added current-CR3 translation and bootstrap identity physical access.
- Added actual PT_LOAD frame allocation, user PTE installation, segment copying and BSS zeroing.
- Added a mapped one-page user stack, Linux initial stack copy, and automatic iretq entry.
- Made assembly/Rust boundaries explicitly SysV64 so the same kernel can be linked into a Microsoft-ABI UEFI image.

## 0.9.0 - 2026-10-12
- Replaced numeric-only user pointer checks with page-table-backed usercopy validation.
- Added effective USER/WRITABLE/PRESENT permission checks and page-boundary chunking.
- Added bounded physical-frame recycling with duplicate-free detection.
- Added transactional ELF page installation and rollback of PTEs and frames on failure.
- Removed unchecked byte writes from the ELF copy path.

## 0.10.0 - 2026-10-12
- Added a per-process bootstrap CR3 cloned from the live firmware root.
- Cleared dedicated PML4 slots before installing the Linux image and user stack.
- Moved the acceptance ELF to a separate 4 TiB PML4 slot.
- Activated the process CR3 immediately before the ring-3 IRET transition.
- Rejected ELF layouts that share the identity slot or cross the private image slot.

## 0.11.0 - 2026-10-12
- Added process address-space lifetime tracking across the CR3 switch.
- Added recursive teardown for private PML4 slots, including user frames and intermediate page tables.
- Restored the bootstrap CR3 before reclaiming the process root.
- Connected exit_group to address-space reclamation before CPU halt.
- Added a single-core QEMU/OVMF serial acceptance runner.

## 0.12.0 - 2026-10-12
- Added containment for user-mode CPU faults with process-only termination and address-space reclamation.
- Added explicit general-protection, page-fault and double-fault entry layouts.
- Recorded process exit status and terminating exception vector.
- Strengthened the Linux acceptance ELF to verify invalid write pointers return raw `-EFAULT`.
- Added distinct success and failure messages and nonzero failure exit status.

## 0.13.0 - 2026-10-12
- Corrected the Microsoft-x64 to SysV64 loader transition stack alignment.
- Added dedicated error-code exception stubs for invalid TSS, segment-not-present, stack-segment and alignment-check faults.
- Cleared DF before entering Rust exception handling.
- Added source consistency and host toolchain preflight scripts.
- Included compiler-builtins memory intrinsics in the cross-target Rust build.

## 0.14.0 - 2026-10-12
- Added QEMU isa-debug-exit signaling for deterministic guest success, ABI failure and user-fault outcomes.
- Added a timeout-bounded acceptance harness that captures and validates serial output.
- Added automated checks for EFAULT success, zero exit status and full address-space reclamation.
- Updated the QEMU runner with the debug-exit device.

## 0.15.0 - 2026-10-12
- Added UART transmitter-ready polling instead of writing bytes blindly.
- Added CRLF normalization for serial terminals.
- Added bounded serial drain before QEMU debug-exit.
- Protected acceptance markers from being lost when the VM exits immediately after process teardown.

## 0.16.0 - 2026-10-12
- Added CPUID detection for SYSCALL/SYSRET, NX, 1 GiB pages, SMEP and SMAP.
- Rejected CPUs that cannot support the required Linux x86-64 entry and NX model.
- Enabled CR0.WP so supervisor writes respect read-only PTEs.
- Added boot diagnostics for detected CPU protections.

## 0.17.0 - 2026-10-12
- Located ACPI RSDP through UEFI configuration tables and passed it through BootInfo.
- Added checksum-validated XSDT/RSDT and MADT discovery.
- Parsed Local APIC, IOAPIC, interrupt-source overrides and LAPIC address overrides.
- Initialized xAPIC, masked the legacy PIC and all IOAPIC redirection entries.
- Added a periodic Local APIC timer vector, full register-preserving IRQ entry and EOI processing.
- Enabled IF in the initial ring-3 RFLAGS.
- Added an interrupt-disabling spin lock for state shared with IRQ handlers.

## 0.18.0 - 2026-10-12
- Added fixed-capacity task descriptors with dynamic PID allocation and task states.
- Added per-task 32 KiB kernel stacks and a SysV64 callee-state context switch.
- Added a round-robin runnable queue, cooperative yield, sleeping tasks and timer wakeups.
- Added timer-driven `need_resched` bookkeeping without unsafe switching inside interrupt context.
- Added kernel-thread creation and a two-thread context-switch self-test.

## 0.19.0 - 2026-10-12
- Added per-task CR3, FS base, TSS.RSP0 and SYSCALL kernel-stack state.
- Applied architecture state before every cooperative context switch.
- Connected `arch_prctl(ARCH_SET_FS)` to the real IA32_FS_BASE MSR.
- Corrected the bootstrap task to use the actual 64 KiB ring-0 stack rather than an unused scheduler stack.
- Extended the scheduler test to verify FS-base isolation across two kernel threads.

## 0.20.0 - 2026-10-12
- Added parent PID tracking and a real task-backed `getppid` result.
- Added fixed-capacity wait queues with block, wake-one and wake-all operations.
- Added scheduler APIs for blocking and waking tasks by PID.
- Added child zombie lookup, exit-status collection and task-slot reuse.
- Extended the scheduler self-test to reap both child kernel threads.

## 0.21.0 - 2026-10-12
- Replaced direct embedded-ELF boot with a read-only initramfs containing `/init` and `/etc/motd`.
- Added checksum-independent, bounds-checked NSAR initramfs parsing and absolute path lookup.
- Added read-only inode metadata and offset-based file reads.
- Added a 32-entry bootstrap FD table with console descriptors and independent file offsets.
- Implemented `openat`, regular-file `read`, `close`, `lseek`, `fstat`, and `newfstatat` paths.
- Extended the Linux acceptance ELF to open and print `/etc/motd` before exiting.

## 0.22.0 - 2026-10-12
- Connected anonymous private `mmap` to physical-frame allocation and user PTE creation.
- Zero-filled every newly allocated anonymous and brk page before making it accessible.
- Connected `mprotect` to hardware PTE writable/NX permissions and TLB invalidation.
- Connected `munmap` to PTE removal and physical-frame recycling.
- Connected upward `brk` growth to mapped read/write heap pages.
- Added rollback when multi-page anonymous mapping fails partway through allocation.
- Extended the ring-3 acceptance program to read/write mmap and brk memory.

## 0.23.0 - 2026-10-13
- Added Linux x86-64 `execve` dispatch for static initramfs ELF files.
- Added bounded, usercopy-backed path, argv, and envp capture.
- Generalized the transactional ELF loader to construct a caller-supplied initial stack.
- Added atomic address-space replacement after the new ELF and stack are fully built.
- Added syscall-return redirection so successful exec resumes at the new entry/RSP and never returns to the old image.
- Added `/bin/hello`; `/init` now execs it with one argument and one environment variable.
- Added ring-3 validation of argc, argv, and envp after exec.

## 0.24.0 - 2026-10-13
- Integrated boot user ELF as a normal runnable child task with its own kernel stack and CR3.
- Returned user exit and faults to the scheduler as zombie tasks, then reaped them from PID 1.

## 0.25.0 - 2026-10-13
- Added bootstrap clock_gettime, nanosleep, and getrandom syscall paths.
- Extended the ring-3 acceptance program with time, sleep, and random checks.

## 0.25.2 - 2026-10-15
- Renamed the project to Slop/MNU: Synthetic Low-quality Operating Platform / Maybe Not Unix.
- Renamed package, target, symbols, artifacts, boot ABI, uname identity, initramfs messages, tests, and documentation.

# Slop/MNU

**SLOP** means **Synthetic Low-quality Operating Platform**. **MNU** means **Maybe Not Unix**.

A clean-room, non-Linux, non-GNU x86-64 kernel aimed at Linux **userspace ABI** compatibility and source-level driver portability.

## Scope of this milestone

This archive is the large first engineering increment, not a claim of full Linux compatibility. It establishes:

- freestanding Rust kernel layout (`no_std`, no external crates)
- x86-64 entry code, serial console, panic path and halt loop
- Linux x86-64 syscall dispatcher with initial `write`, `getpid`, `uname`, `exit`, `exit_group`
- kernel-owned errno and UAPI types
- VFS, task, virtual-memory and device-driver contracts
- ELF64 type definitions and loader validation skeleton
- PCI device model and Linux-driver adaptation boundary
- architecture and clean-room licensing documents
- LLVM-only build path; no GCC, binutils, glibc, GNU make or Linux source

## Build prerequisites

- Rust nightly with `rust-src`
- LLVM `ld.lld`
- QEMU for execution (optional)

```sh
rustup component add rust-src
cargo +nightly build -Zbuild-std=core --release
./tools/link.sh
```

`tools/link.sh` emits `build/slop-mnu.elf`. This first milestone is entered by a Multiboot/UEFI-capable loader; replacing that temporary boot seam with the in-tree UEFI loader is milestone 2.

## License policy

Project-authored code is Apache-2.0. No Linux or GNU source is copied. Do not paste GPL code, generated headers derived from GPL headers, or Linux internal structure layouts. Public ABI facts must be recorded in `docs/compat-ledger.md` with provenance.

## Single-image UEFI acceptance build (v0.8)

```sh
rustup component add rust-src
./tools/build-uefi.sh
```

The output is `build/efi/EFI/BOOT/BOOTX64.EFI`. It contains the loader, no-std Rust kernel, privilege-transition assembly and the embedded static Linux acceptance ELF. This path currently assumes identity-accessible physical RAM in the firmware page tables and is intended for the first controlled QEMU/OVMF run.

## QEMU/OVMF acceptance run

```sh
OVMF_CODE=/path/to/OVMF_CODE.fd \
OVMF_VARS_TEMPLATE=/path/to/OVMF_VARS.fd \
./tools/run-qemu.sh
```

The runner uses one emulated CPU and serial output because the current syscall transition state is global rather than per-CPU. A successful run should print the Linux ELF message, report exit status 0, reclaim the private address space, and halt.

## Build preflight

```sh
./tools/check-toolchain.sh
```

This verifies the nightly Rust toolchain, Clang/LLD utilities, LLVM binary tools, Python, and critical source-level ABI connections before the UEFI build starts.

## Automated Linux ELF acceptance gate

```sh
OVMF_CODE=/path/to/OVMF_CODE.fd \
OVMF_VARS_TEMPLATE=/path/to/OVMF_VARS.fd \
./tools/acceptance-test.sh
```

The harness writes the complete guest console to `build/acceptance-serial.log` and prints `acceptance: PASS` only when the Linux ELF validates `-EFAULT`, exits with status 0, and its private address space is reclaimed.

## Read-only initramfs and VFS (v0.21)

The UEFI image embeds `build/initramfs.nsar`. At boot the kernel mounts it, resolves `/init` through VFS, and executes that regular file. The acceptance program also opens and reads `/etc/motd` through Linux `openat`, `read`, and `close` syscalls. NSAR is a temporary allocation-free bootstrap format, not a stable on-disk filesystem ABI.

## Hardware-backed anonymous memory (v0.22)

Anonymous private `mmap` and upward `brk` growth now allocate zeroed physical frames and install user PTEs. `mprotect` updates writable/NX permissions, while exact-range `munmap` removes PTEs and recycles frames. Partial VMA operations, demand paging, file-backed mappings, COW, and brk shrink remain future work.

## Static execve (v0.23)

`/init` now uses Linux `execve` to replace itself with `/bin/hello` from initramfs. Path, argv, and envp are copied from user memory before a new CR3 is built. The old image remains active on load failure; on success SYSRET is redirected to the new ELF entry and stack.

# Architecture

Slop/MNU uses a modular monolithic kernel for the first compatibility target. Rust owns memory-safe policy and object lifetimes; small assembly files own privilege transitions; C is reserved for clean-room source adapters for drivers whose original upstream license permits reuse.

## Compatibility planes

1. **Linux userspace ABI:** x86-64 ELF, syscall numbers, errno, signals, `/proc`, `/sys`, sockets, epoll, futex, ioctls and device nodes.
2. **Driver source portability:** a generated compatibility facade maps a documented subset of Linux driver-facing concepts onto Slop/MNU's native driver API.
3. **Hardware behavior:** PCIe, ACPI, interrupt controllers, DMA/IOMMU, USB, NVMe, networking and graphics are implemented from hardware specifications or permissively licensed references.

Binary `.ko` compatibility is intentionally not the primary design. Linux has no stable in-kernel binary ABI. A version-pinned module capsule may be researched later, but it is a VM-like compatibility product, not the native driver model.

## Kernel subsystems

- `arch`: trap/syscall/context-switch and MMU details
- `vm`: physical allocator, address spaces, copyin/copyout, mmap
- `task`: threads, processes, credentials, namespaces and signals
- `vfs`: inode/dentry/file model and filesystem registration
- `linux_abi`: translation layer, never the kernel's internal API
- `driver`: bus-neutral device graph, resources, DMA and interrupts

# Driver compatibility strategy

"Linux drivers" are not a single stable ABI target. Slop/MNU splits the problem:

- userspace-visible device ABI compatibility: device nodes, ioctl payloads, sysfs/procfs/netlink behavior;
- source portability: recompile a legally compatible driver against a versioned Slop/MNU facade;
- hardware enablement: native Rust drivers written from vendor specifications;
- optional legacy capsule: execute a narrowly pinned driver in an isolated compatibility domain.

The facade must never expose Slop/MNU internals. It uses opaque handles, generated layout assertions and explicit lifecycle rules. Each supported Linux API profile is versioned and tested independently.

# Linux compatibility target

The first executable target is a statically linked x86-64 Linux program using a small libc startup path. Compatibility is measured at the raw syscall boundary, ELF process image, initial stack and userspace-visible device interfaces.

## Implemented bootstrap surface

`read`, `write`, `close`, `fstat`, `brk`, `sched_yield`, identity calls, PID/TID calls, `uname`, `arch_prctl` FS-base state, `set_tid_address`, `set_robust_list`, `prlimit64`, `exit`, and `exit_group`.

## Deliberately not claimed yet

`mmap`, `mprotect`, `munmap`, signals, futex waiting/waking, clocks, random data, path lookup, dynamic linking, fork/clone and sockets. Returning `ENOSYS` is preferable to silently violating Linux semantics.

## Acceptance gate

A release only advances to "runs Linux binaries" when the same statically linked test ELF produces matching stdout, exit status, syscall results and errno values on Linux and Slop/MNU under an automated differential harness.

# Milestone 10: first process-owned CR3

The acceptance process no longer inserts user PTEs directly into the firmware root. A new PML4 frame is allocated, the live root is copied to preserve the executing PE image, kernel stacks, serial I/O path, BootInfo and identity-accessible RAM, and dedicated user slots are cleared before mapping.

The test ELF is linked at 4 TiB (`0x0000040000000000`), giving it PML4 slot 8. The stack remains near the top of the lower canonical half in slot 255. Both slots are private in the new root. Layouts that use slot 0 or cross the image slot are rejected.

Immediately before IRETQ, CR3 is loaded with the process root. The syscall kernel path remains mapped because the rest of the firmware root was copied. This is an isolation step, not a final kernel address-space design: low firmware mappings and most other firmware PML4 entries are still inherited. The next stage is a deliberate kernel-only mapping set and a physical direct map rather than wholesale firmware inheritance.

# Milestone 11: process exit and address-space reclamation

The first Linux process now has an explicit lifetime. Before ring-3 entry, the kernel records the bootstrap CR3, process CR3, ELF PML4 slot, and stack PML4 slot. `exit_group` reaches `task::exit`, which switches back to the bootstrap CR3 before touching page-table frames owned by the process.

Each private slot is then walked through PDPT, PD, PT, and leaf PTE levels. User frames are returned to the physical allocator, empty PT/PD/PDPT frames are returned, the PML4 entry is cleared, and finally the process PML4 frame itself is recycled. Shared firmware/kernel entries are never traversed or released because only slots cleared before process construction are registered as private.

The teardown is intentionally limited to 4 KiB mappings. A large-page entry in a private slot is rejected. When huge pages are introduced, teardown must handle their ownership explicitly.

`tools/run-qemu.sh` provides the first reproducible acceptance invocation for QEMU with OVMF, one CPU, serial output, and the generated FAT directory. Paths to OVMF firmware can be overridden with `OVMF_CODE` and `OVMF_VARS_TEMPLATE`.

# Milestone 12: user-fault containment and ABI self-test

CPU exceptions now pass vector, error code, RIP, and CS to Rust. Page fault, general protection, and double fault have dedicated assembly stubs because the CPU already pushes an error code for those exceptions. Exceptions originating at CPL3 are recognized through `CS & 3` and terminate only the active Linux process. The kernel first records a signal-like status, switches back to the bootstrap CR3, reclaims the private address space, and halts the acceptance CPU. Ring-0 exceptions remain fatal kernel exceptions.

The static Linux ELF now begins with a negative test: `write(1, 0x1234, 8)` must return raw `-EFAULT` (`-14`). It then performs the valid console write and checks the returned byte count. Any mismatch emits a failure message on fd 2 and exits with status 1. Success emits `hello from a Linux ELF on Slop/MNU; EFAULT passed` and calls `exit_group(0)`.

This improves the meaning of a successful boot. It demonstrates not only ring-3 execution and SYSCALL/SYSRET, but also Linux raw errno behavior, page-table-backed user-pointer validation, a successful user-buffer copy, and process teardown.

# Milestone 13: ABI hardening and build preflight

The UEFI loader is compiled with the Microsoft x64 ABI while the kernel entry is explicitly SysV64. The transition stub now subtracts eight bytes before `call`, so the SysV callee observes the required stack alignment. BootInfo remains passed in RDI.

Exception stubs now distinguish additional CPU-error-code vectors: invalid TSS (10), segment not present (11), stack-segment fault (12), general protection (13), page fault (14), alignment check (17), and double fault (8). `tools/check-source.sh` checks critical ABI and ownership connections without compiling. `tools/check-toolchain.sh` verifies all required host commands and runs the source checks. The UEFI build invokes this preflight before producing artifacts.

The Rust cross-target build now includes `compiler_builtins` with memory intrinsics through `-Zbuild-std`. This reduces dependence on host CRT implementations when linking the freestanding PE/COFF image, while the loader still supplies the basic C memory symbols needed by Clang-generated code.

# Milestone 14: deterministic acceptance result

A halted VM is ambiguous: it may mean a successful `exit_group`, a kernel deadlock, or a fatal exception. The bootstrap test now writes a result byte to QEMU's `isa-debug-exit` device after process teardown. - QEMU host status 33, corresponding to guest value `0x10`.
- The Linux ELF success marker containing `EFAULT passed`.
- A zero task exit status.
- Confirmation that the process address space was reclaimed with vector zero.
- Absence of the ABI failure marker and kernel-exception marker.

This turns the first Linux-program goal into a machine-checkable gate rather than a visual inspection of serial output. The actual guest execution remains to be performed in the user's build environment.

# Milestone 15: reliable serial acceptance output

The automated gate depends on the final process-reclamation marker being visible before QEMU exits. The earlier serial writer sent bytes directly to COM1 and could overrun the UART FIFO or terminate the VM before the last bytes left the transmitter.

The console now polls the line-status register before every byte, normalizes newline to CRLF, and exposes `console::flush`. Polling loops are bounded so a missing UART cannot hang the kernel forever. The QEMU debug-exit path drains the transmitter before writing to port `0xf4`.

# Milestone 16: CPU capability gate and write protection

The bootstrap now validates architectural prerequisites instead of assuming every x86-64 environment supports the selected entry path. Extended CPUID checks require SYSCALL/SYSRET and NX before their MSRs or PTE bits are used. Optional 1 GiB page, SMEP, and SMAP capabilities are reported for later stages.

# Milestone 17: interrupt-controller and timer foundation

The UEFI loader now locates ACPI 1.0/2.0 RSDP entries in the system configuration table, preferring ACPI 2.0, and passes the pointer through BootInfo. The kernel validates RSDP, root table, and MADT checksums before consuming controller addresses. MADT parsing records the Local APIC address, first IOAPIC, ISA interrupt-source overrides, and Local APIC address override.

The bootstrap masks both 8259 PICs, enables xAPIC through IA32_APIC_BASE, enables the Local APIC software bit, masks LINT0/LINT1, and masks every IOAPIC redirection entry. External device IRQs therefore cannot enter until an explicit route is installed. The Local APIC timer runs periodically on vector 0x40. Its assembly entry preserves general-purpose registers, calls a Rust tick handler, writes EOI, restores registers, and returns with IRETQ.

Initial user RFLAGS now includes IF (`0x202`). The acceptance ELF can therefore be interrupted while running in ring 3, with hardware stack switching through TSS.RSP0. Kernel entry through SYSCALL still masks IF using IA32_FMASK, so the current global syscall stack cannot be recursively used by timer preemption.

The timer count is intentionally uncalibrated. It proves interrupt delivery but is not yet a time source. HPET or PIT calibration is required before ticks can represent nanoseconds or drive a fair scheduler quantum.

`IrqSpinLock` saves IF, disables local interrupts while held, and restores the previous IF state on release. This is the required locking primitive for run queues and timer queues shared with interrupt context.

Before entering user mode, the kernel performs a bounded Local APIC timer self-test. It enables IF, executes HLT, receives periodic timer interrupts, disables IF again, and requires the tick counter to advance. The acceptance harness now requires the marker `local APIC timer and EOI passed`, making timer delivery part of the automated gate.

`route_isa` converts an ISA IRQ through MADT interrupt-source overrides, applies active-low and level-trigger flags, selects the bootstrap Local APIC as destination, and programs the matching IOAPIC redirection entry. All routes remain masked unless a driver explicitly requests otherwise.

# Milestone 18: scheduler and kernel-thread foundation

Slop/MNU now has a single-CPU fixed-capacity scheduler with eight task slots. Each task records PID, scheduling state, saved kernel RSP, kernel-stack top, wake tick, and exit status. Task states include unused, running, runnable, sleeping, and zombie. PIDs are allocated dynamically from 2 while the bootstrap task remains PID 1.

Each task slot owns a 32 KiB aligned kernel stack. New kernel threads receive a synthetic switch frame containing the SysV64 callee-preserved register set and a return target for `kernel_thread_trampoline`. The initial stack includes an alignment bias so the trampoline observes the required SysV function-entry alignment.

`switch_context` saves RBP, RBX, and R12-R15, stores the old RSP, loads the next RSP, restores the next task's preserved state, and returns into that task. The scheduler selects runnable tasks round-robin while holding `IrqSpinLock`, but releases the queue lock before performing the assembly switch.

The Local APIC timer increments ticks, wakes sleeping tasks and sets an atomic `need_resched` flag. It deliberately does not switch tasks inside the IRQ handler yet. Full timer preemption requires an interrupt-frame-aware return path capable of replacing the interrupted context safely. Cooperative `yield_now` and `sleep_until` are active now.

A boot-time self-test creates two kernel threads. Each advances a counter, yields, resumes, advances again, and exits into zombie state. The test passes only after both counters reach two, demonstrating separate kernel stacks and bidirectional context switching. # Milestone 20: wait queues and zombie reaping

Tasks now record a parent PID when created. The Linux `getppid` syscall reads this scheduler relationship instead of returning a constant zero. The bootstrap task remains parentless, while kernel threads created by it receive PPID 1.

# Milestone 22: hardware-backed anonymous VM and brk

Anonymous private mappings now allocate one physical frame per page, clear the frame through the bootstrap physical-access mapping, and install a user PTE in the currently active process page table. PTE permissions are derived from Linux protection bits: writable follows `PROT_WRITE`, executable pages clear NX, and non-executable pages set NX. Every mapping remains user-accessible.

`mmap` first reserves a VMA and then maps pages. If frame allocation or page-table insertion fails partway through, all successfully mapped pages are removed and recycled, and the VMA reservation is rolled back. `MAP_FIXED` currently rejects overlap rather than replacing an existing mapping, which avoids destructive partial replacement until VMA splitting is implemented.

`mprotect` updates each leaf PTE through `protect_page`, including TLB invalidation, then updates the VMA ledger. `munmap` removes every leaf PTE, invalidates it, recycles the frame, and removes the exact VMA. Partial VMA ranges are not accepted yet.

Upward `brk` growth reserves an anonymous read/write VMA and maps zero-filled pages between the old and new page boundary. Shrinking is conservatively rejected until adjacent brk extents can be merged and split transactionally. Linux semantics are preserved by returning the old break on failure.

The ring-3 acceptance program now requests a writable anonymous page, verifies zero fill, writes and reads a value, changes the page to read-only with `mprotect`, unmaps it, grows brk by one page, verifies zero fill, and writes and reads heap data. Its success marker is `VFS, VM and EFAULT passed`.

# Milestone 23: transactional static execve

Slop/MNU now dispatches Linux x86-64 syscall 59 and resolves the executable path through the read-only initramfs VFS. # Milestone 7: ring 3 and system-call boundary

The kernel now has source-level CPU paths for entering a 64-bit user context and receiving Linux x86-64 `syscall` instructions.

# Milestone 8: first end-to-end Linux ELF path

This increment connects the previously isolated parts into one acceptance path:

1. Build a static syscall-only Linux ELF.
2. Convert that binary into a COFF object.
3. Compile the no-std Rust kernel as a COFF static library.
4. Link loader, kernel, assembly transitions and embedded ELF into `BOOTX64.EFI`.
5. Pass the embedded ELF as the BootInfo initrd.
6. Reuse the firmware's active CR3 for the initial single-process experiment.
7. Allocate zeroed frames, install user PTEs, copy PT_LOAD bytes, and zero BSS.
8. Map a writable, non-executable user stack and build the Linux initial stack within it.
9. Enter ring 3 through IRETQ.
10. Receive `write` and `exit_group` through the SYSCALL path.

## Deliberate bootstrap assumptions

The `Identity` physical accessor assumes that page-table frames and newly allocated conventional RAM remain identity-addressable in the firmware page tables. This is suitable only for the first controlled UEFI/QEMU acceptance run. It is not a portable UEFI guarantee and must be replaced by a kernel-owned direct map.

The active firmware CR3 is modified instead of installing a process-owned root. This avoids losing live PE image mappings before a direct map and kernel mapping copier exist, but it provides no process isolation.

Only a single static ET_EXEC program is accepted. Dynamic ELF, PIE relocation, file-backed mmap, multiple tasks, signals, scheduler preemption and resource reclamation remain outside this acceptance gate.

The first user entry clears IF because no IRQ routing or timer acknowledgement exists yet. Enabling user interrupts before PIC/APIC handling could route an interrupt into the fatal default exception gate. IF will be enabled after the minimal Linux ELF acceptance test and interrupt-controller initialization are both stable.

The acceptance ELF is linked at `0x0000004000000000`, outside the low physical identity range normally populated by firmware. This avoids colliding with firmware large-page entries while reusing the current CR3. The page-table walker rejects a large-page entry instead of treating it as a next-level table. Newly created ancestor entries propagate the USER bit, and EFER.NXE is enabled before any NX PTE is installed.

# Milestone 9: recoverable memory boundaries

The first Linux program uses `write`, whose buffer is a user pointer. Earlier versions validated only the numeric lower-half range and could fault the whole kernel on an unmapped address. Usercopy now walks the active page tables before every chunk, verifies effective ancestor and leaf permissions, translates to physical memory, and copies only up to the current page boundary. Invalid, supervisor-only, non-present, or read-only destinations return `EFAULT` without dereferencing the virtual pointer.

ELF installation is now transactional. Every newly mapped `(virtual, physical)` page is recorded. If segment copying, BSS initialization, stack allocation, or stack construction fails, pages are unmapped in reverse order and frames enter a bounded recycle stack. Successful installation explicitly commits the transaction.

This does not yet recover from machine-checks or stale firmware mappings, and the identity physical accessor remains the principal bootstrap limitation. It does close the normal unmapped-user-pointer failure path for the first process.
